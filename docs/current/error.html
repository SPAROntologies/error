title
The Error Ontology
description
The **_Error Ontology_** is an unit test that allow to produce an inconsistent model if a particular (and incorrect) situation happens. ![The main architecture of the Error Ontology.](error.png) It works by means of a data property `error:hasError` that denies its usage for ant resource. In fact, by defining its domain as "all those resource that do not have any `hasErrorDescription` assertion", a resource that asserts having an error makes the ontology inconsistent. ## Examples of use In the following subsections, we introduce some examples to showcase how to use the Error Ontology. The prefixes that are used in all the examples provided below are defined as follows: @prefix : <http://www.sparontologies.net/example/> . @prefix error: <http://www.essepuntato.it/2009/10/error#> . @prefix fabio: <http://purl.org/spar/fabio/> @prefix owl: <http://www.w3.org/2002/07/owl#> . @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> . @prefix xsd: <http://www.w3.org/2001/XMLSchema#> . ### Flagging an erroneous resource A resource can be directly marked as erroneous by asserting a description of its error. Since no resource can have any `error:hasError` assertion, a reasoner will classify it as a member of `owl:Nothing`, making the model inconsistent. :my-article a fabio:Article ; error:hasError "The article has two different publication dates."^^xsd:string . ### Defining a forbidden situation through a class axiom An incorrect situation can be modelled as a class whose members are automatically associated with an error description. Any individual that falls in such a class makes the model inconsistent, and the error description explains why. :DraftAndPublishedDocument owl:equivalentClass [ a owl:Class ; owl:intersectionOf ( fabio:Manuscript fabio:JournalArticle ) ] ; rdfs:subClassOf [ a owl:Restriction ; owl:onProperty error:hasError ; owl:hasValue "A document cannot be a draft and published at the same time."^^xsd:string ] . :my-document a fabio:Manuscript , fabio:JournalArticle . ## Competency Questions The Error Ontology can be used to produce an inconsistent model if a particular (and incorrect) situation happens. In the following subsections, some competency questions are introduced together with their respective SPARQL queries. The prefixes that are used in all the SPARQL queries provided below are defined as follows: PREFIX error: <http://www.essepuntato.it/2009/10/error#> PREFIX owl: <http://www.w3.org/2002/07/owl#> PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#> ### CQ1 Which resources are explicitly asserted to have an error, and what is the description of that error? SELECT ?resource ?description WHERE { ?resource error:hasError ?description . } ### CQ2 Which classes describe a forbidden situation, and what is the error description associated with their members? SELECT ?class ?description WHERE { ?class rdfs:subClassOf ?restriction . ?restriction a owl:Restriction ; owl:onProperty error:hasError ; owl:hasValue ?description . } ### CQ3 Does the dataset contain at least one resource with an error? ASK { ?resource error:hasError ?description . }
